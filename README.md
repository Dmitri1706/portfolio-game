# Портфолио-игра Дмитрия Мельшина

Изометрическая пиксельная мини-игра-портфолио на **Phaser 3 + Vite + TypeScript**.

## Команды

Все команды выполняются в папке проекта (`C:\Projects\portfolio-game`).

| Команда | Что делает |
|---|---|
| `npm install` | Скачивает библиотеки (один раз, после скачивания проекта) |
| `npm run dev` | Запускает игру локально: откройте в браузере http://localhost:5173 |
| `npm run sprites` | Заново рисует все спрайты в `public/assets/sprites/` |
| `npm run build` | Собирает готовый сайт в папку `dist/` |

Остановить локальный сервер: в его окне терминала нажмите `Ctrl + C`.

## Графика: 3D-диорамы из Blender

С версии после тега `pixel-version` графика рендерится в Blender (установлен в `C:\Tools\blender`). Всё строится скриптами — открывать Blender руками не нужно.

| Команда | Что делает | Время |
|---|---|---|
| `npm run render:lobby` | Рендер лобби в финальном качестве | ~15 мин |
| `npm run render:lobby:preview` | Быстрый черновик лобби | ~3 мин |
| `npm run render:vhod` | Рендер комнаты «В ХОД» | ~10 мин |
| `npm run render:sport` | Рендер комнаты «Спортмастер» | ~10 мин |
| `npm run render:character` | Все анимации персонажа | ~3 мин |
| `npm run render:character:preview` | Черновик персонажа | ~1 мин |
| `npm run render:people` | Зрители в зале, покупатель и фоновые покупатели | ~5 мин |
| `npm run render:items` | Предметы в руках (газета, телефон, папка, кроссовки) | ~1 мин |

- **Описание комнаты** — `rooms/lobby.json`, `rooms/vhod.json`, `rooms/sport.json`: размер, двери и окна на стенах (`walls`), мебель на полу (`objects`, клетки `x`, `y`, размер `w × d`, поворот `face`). У интерактивных предметов — `interact` (куда подходит персонаж, куда смотрит, куда садится), у стульев в зале — `spectator` (кто сидит), у полок магазина — `section` (секция мини-игры). Поменяли — перерендерили. Этот же файл игра читает для сетки проходимости и предметов.
- **Люди** — варианты в `blender/build_character.py` (`VARIANTS`): цвета одежды и волос, очки, причёска. Листы — `public/assets/sprites3d/<вариант>_<анимация>.webp`, описание — `src/assets/characters/<вариант>.json`.
- **Модели** — `blender/models.py` (мебель, двери, лампы, растения), **камера, свет и материалы** — `blender/lib.py`, **рендер комнаты** — `blender/build_room.py`, **персонаж** — `blender/build_character.py`.
- **Результат:** `public/assets/rooms/<комната>/` (фон `bg.webp` + вырезки предметов + двери в двух состояниях) и `src/assets/rooms/<комната>.layout.json` (где что лежит). Персонаж — `public/assets/sprites3d/player_<анимация>.webp` и `src/assets/player3d.json`.
- Вернуться к пиксельной версии: `git checkout pixel-version` (обратно — `git checkout master`).

## Тексты, ссылки и материалы (без программирования)

Всё, что вы будете менять, лежит в папке `content/` и `public/materials/`. Код трогать не нужно. Пока запущен `npm run dev`, изменения появляются в браузере сами.

### Тексты кейсов — `content/cases/*.md`

| Файл | Где показывается |
|---|---|
| `content/cases/site.md` | Компьютер (сайт) в комнате «В ХОД» |
| `content/cases/presentation.md` | Сцена со зрителями |
| `content/cases/mediakit.md` | Газета-медиакит |
| `content/cases/webinar.md` | Телефон с вебинаром |
| `content/cases/event.md` | Трибуна с микрофоном (мероприятие по HR-автоматизации) |
| `content/resume.md` | Папка-резюме. Страницы папки разделяются строкой `---` |
| `content/cases/sportmaster.md` | Доска «Лучший продавец» в комнате «Спортмастер» |

Это обычный текст в формате Markdown:
- первая строка после заголовка `# …`, целиком **жирная**, — строка-итог кейса: в окне она выделяется плашкой;
- `## Заголовок` — заголовок раздела (Задача, Ограничения, Что я сделал, Результат, Инструменты);
- строка, начинающаяся с `- ` — пункт списка;
- `**жирный**`, `_курсив_`;
- `[текст ссылки](https://адрес)` — ссылка;
- всё между `<!--` и `-->` — подсказка, на сайте не видна.

### Ссылки, пути к файлам и контакты — `content/settings.json`

```json
{
  "role": "Product / Маркетолог",
  "site": {
    "url": "https://адрес-сайта.ru",
    "embed": true,
    "screenshot": "materials/site-screenshot.webp"
  },
  "presentation": { "pdf": "materials/presentation.pdf" },
  "mediakit": { "pdf": "materials/mediakit.pdf" },
  "webinar": {
    "url": "https://rutube.ru/video/private/…/?p=…",
    "embed": "https://rutube.ru/play/embed/…/?p=…"
  },
  "event": { "photo": "materials/event.jpg" },
  "resume": { "pdf": "materials/resume.pdf" },
  "contacts": {
    "telegram": "username",
    "email": "mail@example.com",
    "phone": "+7 900 000-00-00",
    "showPhone": false,
    "city": "Краснодар"
  }
}
```

- `role` — подпись под именем на экране загрузки, в быстром просмотре и в превью ссылки.
- `site.url` — ваш сайт для компьютера. Если сайт не открывается внутри «монитора» (некоторые сайты запрещают встраивание), поставьте `"embed": false` — тогда показывается только длинный скриншот `site.screenshot` (его можно прокручивать), без живого сайта. Сейчас стоит именно так. Кнопка «Открыть сайт в новой вкладке» есть всегда.
- `webinar.url` — обычная ссылка на видео из адресной строки: VK Видео, Rutube или YouTube. По ней работает кнопка «Смотреть на Rutube». Пустые кавычки `""` — показывается заглушка.
- `webinar.embed` — адрес для встраивания видео в «телефон» (необязательно). Если его нет, игра сама попробует составить его из `url`.
- `event.photo` — фото с мероприятия для окна у трибуны. Положите фото в `public/materials/` и впишите путь. Пустые кавычки `""` — показывается заглушка.
- `contacts.telegram` — имя пользователя без `@`. Пустое поле `""` — контакт не показывается.
- `contacts.showPhone` — показывать ли телефон. `false` — телефон скрыт везде, `true` — показан в окне «Связаться» и в быстром просмотре.
- `contacts.city` — город, показывается простым текстом.
- Пути к файлам пишутся от папки `public/`: файл `public/materials/resume.pdf` → `"materials/resume.pdf"`.

**Как не сломать JSON:**
1. Текст — всегда в двойных прямых кавычках: `"так"`. Не «ёлочки» и не одинарные.
2. Между парами `"ключ": "значение"` ставится запятая, а **после последней пары в блоке — нет**.
3. `true` / `false` пишутся без кавычек.
4. Скобки `{ }` должны быть парными. Не удаляйте ключи слева от двоеточия — меняйте только значения справа.
5. Если после правки игра показала ошибку — проверьте файл на сайте jsonlint.com (вставьте текст и нажмите Validate).

### Диалог продажи — `content/dialog.json`

Сценарий разговора с покупателем в комнате «Спортмастер». Правила JSON — те же, что выше.

- `names` — имена над портретами (`seller` — вы, `customer` — покупатель).
- `doubt` — плашка после неудачного ответа («Покупатель задумался…»).
- `steps` — шаги разговора по порядку. У каждого шага `title` (подпись сверху) и `options` — варианты ответа:
  - `text` — что говорит продавец;
  - `"correct": true` — правильный вариант, ведёт к следующему шагу. Без него вариант считается неудачным: покупатель отвечает с сомнением, и можно выбрать снова;
  - `reply` — ответ покупателя. Либо одна строка, либо разные ответы для двух сценариев: `{ "A": "…", "B": "…" }`;
  - `"scenario": "A"` или `"B"` — вариант показывается только в этом сценарии. Сценарий выбирается случайно при каждом новом разговоре;
  - `bonus` — плашка за допродажу в конце (например `"+ допродажа 🧦"`).
- `final` — последняя фраза покупателя, `closed` — надпись «Продажа закрыта!», `noBonus` — подпись, если допродажи не было.

Варианты ответов показываются в случайном порядке — правильный не всегда первый.

### Звуки и музыка — `content/settings.json` → `"audio"`

Сейчас все звуки и 8-битная музыка генерируются кодом. Звук выключен по умолчанию и включается кнопкой 🔊.

Чтобы заменить любой звук своим файлом: положите файл (mp3, ogg или wav) в `public/audio/` и пропишите путь:

```json
"audio": {
  "music": "audio/music.mp3",
  "bump": "audio/bump.wav",
  ...
}
```

| Ключ | Когда звучит |
|---|---|
| `music` | Фоновая музыка (играет по кругу) |
| `step` | Шаги |
| `door` | Открывается дверь |
| `fall` / `land` | Падение сверху / приземление |
| `bump` | Спотыкание о заколоченную дверь («бум») |
| `pickup` / `place` | Взял предмет / поставил кроссовок |
| `type` | Печать текста в диалоге |
| `applause` | Аплодисменты зрителей |
| `achievement` | «Дзынь» ачивки |

Пустые кавычки `""` — звук генерируется кодом.

### Адрес сайта для превью в соцсетях — `content/settings.json` → `"siteUrl"`

Telegram и соцсети показывают картинку-превью только по полному адресу. После публикации (Этап 6) впишите адрес сайта, например `"siteUrl": "https://имя.github.io/portfolio-game/"`. Сама картинка — `public/og-image.png` (1200×630), иконки сайта — `public/favicon-16.png`, `favicon-32.png`, `apple-touch-icon.png`. Их рисует `npm run sprites`; чтобы заменить своими, впишите имена в `custom-sprites.txt` (см. ниже).

### Аналитика

В `src/analytics.ts` есть функция-заглушка `track(событие, параметры)`. Её уже вызывают ключевые события: `door_enter` (вход в дверь), `object_use` (открытие предмета), `dialog_end` (конец диалога продажи), `achievement` (ачивки), `final_window`, `contacts_open`, `quick_view`, `sneaker_place`. Сейчас она ничего не отправляет. Чтобы подключить Яндекс Метрику: вставьте код счётчика в `index.html` и `quick.html`, а в `track` добавьте строку `ym(НОМЕР_СЧЁТЧИКА, 'reachGoal', event, params)`.

### Цвета акцентов «В ХОД»

Неоновые цвета комнаты задаются в `scripts/lib/palette.mjs` (строки `vhodNavy`, `vhodNeon`, `vhodNeon2`). Поменяйте цвета и выполните `npm run sprites` — все спрайты перерисуются.

## Спрайты: как заменить на свои

Все картинки описаны в одном манифесте — `src/assets/sprites.json`. Игра берёт PNG по имени файла из `public/assets/sprites/`.

**Заменить спрайт = положить свой PNG с тем же именем и тем же размером.**

Чтобы `npm run sprites` не перезаписал ваш файл, впишите его имя отдельной строкой в `public/assets/sprites/custom-sprites.txt` (создайте файл, если его нет).

Общие требования: PNG с прозрачностью, без сглаживания (чёткие пиксели), изометрия 2:1 (на 2 пикселя вбок — 1 вверх/вниз), свет сверху слева.

## Шрифты

Лежат в `src/assets/fonts/`, из интернета не загружаются. Все под свободной лицензией SIL OFL.

- **Press Start 2P** — заголовки и кнопки (пиксельный, с кириллицей).
- **Tiny5** — надписи в игре: облачка, таблички (маленький пиксельный, с кириллицей).
- **PT Sans** — длинные тексты.

## Как устроен код

- `src/iso.ts` — перевод координат экран ↔ сетка.
- `src/world/IsoRoom.ts` — комната: пол, стены, предметы на стенах, проходимость клеток, поиск пути.
- `src/world/Player.ts` — персонаж: ходьба по пути, повороты, анимации, падение.
- `src/world/Interactable.ts` — интерактивный предмет: подсветка контуром, искорки на телефоне.
- `src/scenes/RoomScene.ts` — общая основа комнат (ходьба, предметы, двери, падение сверху, облачка).
- `src/scenes/LobbyScene.ts`, `VhodScene.ts`, `SportScene.ts` — сами комнаты.
- `src/ui/` — окна поверх игры, правила, кнопки, экран загрузки.
- `src/texts.ts` — игровые фразы.
- `scripts/generate-sprites.mjs` и `scripts/sprites/` — генератор спрайтов.
